FIELD NOTES / PROCESS

How the model works

Follow one UTF-8 byte from text entry to a sensor-decoded byte stream.

01

ENCODE

Text becomes bits

The message is encoded as UTF-8 bytes. Each byte is displayed as eight bits, most-significant bit first. The key is also encoded as UTF-8 and repeated to match the message length.

H → 01001000
02

DRIVE

Bits become pump settings

Each input bit selects a conceptual pulse: bit 0 maps to 18 kPa for 80 ms; bit 1 maps to 32 kPa for 150 ms. These are illustrative model values, not hardware specifications.

0 → 18 kPa · 80 ms
1 → 32 kPa · 150 ms
03

COMPUTE

The maze applies logic

The main path computes input bit XOR key bit. A side branch counts input AND key as a diagnostic. XOR produces a reversible teaching example; it is not a secure encryption algorithm.

cipher bit = input bit XOR key bit
AND branch = input bit AND key bit
04

READ

A sensor thresholds the signal

A modeled optical intensity is assigned to each XOR output: 24 for dry / 0 and 76 for wet / 1. The chosen threshold converts that level back into a bit. Raising it above 76 demonstrates sensor misreads.

intensity ≥ threshold → sensor bit 1
05

DECODE

The sensor bytes can be checked

The displayed HEX stream is assembled from sensor bits. For an ideal threshold, XORing those bytes with the same repeated demo key reproduces the original UTF-8 message. If the sensor threshold causes bit errors, the round-trip check can fail or show replacement characters.

decoded byte = sensed byte XOR repeated key byte
What this app does not simulate: fluid flow, viscosity, channel geometry, pump dynamics, collisions, electrical PWM, photodiode response, or Navier–Stokes equations. The “maze” is a visual model of Boolean operations only.

READ BEFORE USE

Model boundaries & safety

This project is software for learning and demonstration only.

!

IMPORTANT

Not a real crypto system

The “cipher” here is repeated-key XOR. It is deterministic, trivially reversible, and unsuitable for confidentiality, authentication, or protecting any data. Never enter secrets, passwords, personal records, or production data.

01

No physical hardware

The app controls no pump, valve, laser, photodiode, circuit, or microfluidic chip. Pressure, pulse duration, optical intensity, and duration are illustrative values generated in software.

02

No fluid solver

The logic maze does not calculate fluid mechanics or solve Navier–Stokes equations. It models bitwise XOR and AND, then maps the result to simple sensor values.

03

Threshold artifacts are artificial

Sensor errors are created only by moving the threshold outside the modeled dry/wet intensity levels. This is not a calibrated optical or electrical sensor model.

04

Local and offline

Inputs and run logs stay in the app on this device. Exporting creates a JSON file in the browser or app's normal download/share location; it is not uploaded.

05

Educational use only

Use the simulator to explore bit encoding, simple Boolean logic, thresholds, and signal visualization. Do not use it to guide hardware construction, safety decisions, or security design.
